# 安卓离线同行同步

## 0.2 小队旅行：2～5 人

Android 10（API 29）及以上可在“旅行”页新建小队旅行。建队者一次填写 2～5 个不同名字，第一位为自己；每位成员登记一台安卓手机。旧版双人旅行继续按下文使用，不能把双人邀请码当成小队邀请码。

1. 建队者分享本小队邀请码。其他人粘贴后选择自己的名字；**首次登记须与建队手机连通**。登记成功后可各自离线记账，并在与任意已登记成员再次相遇时补传。相同名字不能登记到第二台设备；名额固定，当前没有替换设备或改成员名单的界面。
2. 打开这趟旅行后，手机开始在前台发现同伴。酒店 Wi-Fi、系统热点的 TCP 和蓝牙 LE L2CAP 使用同一加密增量协议；应用按可用链路自动连接。无互联网时仍能本机保存；若两机互相不可达，记录暂存到下次相遇。
3. 每台已登记手机都保留完整账本，并可把已收到的记录传给另一台已登记手机。建队手机离线后，已登记成员仍可互相补传。数据是否已在**全部**成员间收敛，需要各成员至少通过可用链路完成交换；邀请码本身不传账。

小队模式支持原始资金、共同与个人支出、补充现金、成员还款、换汇与单笔删除。共同支出按所有成员平摊，最小货币单位按成员固定顺序分配。余额与结算按成员、按货币从流水计算。当前小队模式**仅在安卓原生客户端实现**：Windows、网页、iOS 和 HTTPS 云中转不能加入，也不能替小队转发。小队页不提供双人模式的手动地址或蓝牙开关。

首次登记把姓名席位绑定到设备公钥，由建队设备签发；会话相互验证并用临时密钥加密传输。分批记录提交 SQLite 后才确认保存；中断重连比较索引补缺，重复数据不重复入账。整趟旅行的本地删除不构成全队删除；已用过的席位不会因为本机删旅行而自动释放。

0.2 小队版已在 Android 16 模拟器完成 50 项协议、数据库、传输和界面检查；此前双人版另在 Android 10 与 Android 16 模拟器完成 45 项检查。测试使用逻辑设备与虚构记录。实际热点隔离、蓝牙无线表现和厂商系统的后台策略仍需用实体手机验收。当前应用打开时同步，锁屏和后台不承诺即时传输。相关测试见 [测试说明](../tests/README.md)。

## 双人直连：热点与经典蓝牙（0.1.5 起）

2026-11-05，安卓 v0.1.5。目标是两台安卓手机独立记账、相遇后同步，不依赖电脑或云服务。最低系统版本保持 API 26；重点覆盖 Android 10 及以上。iOS 保持暂停。

## 使用与连接

只由一人新建旅行，另一人使用同一邀请码加入，并确认自己的身份。邀请码包含旅行密钥；蓝牙配对本身不会自动加入旅行。两台手机都加入同一旅行后，任一手机都能主动连接或接收连接，两端都保留完整 SQLite 数据。整趟旅行的本机删除、货币快捷列表和设备身份仍只影响当前设备；各类流水和单笔删除标记会同步。

热点通过系统设置开启，另一台手机连接。账本没有固定主机角色；提供 Wi-Fi 热点的那台手机承担无线接入点角色。应用同时监听随机 TCP 端口，使用 NSD 广播协议版本和随机设备 ID；备用 UDP 在 45871 端口发送小型发现报文，并尝试子网广播与 Wi-Fi DHCP 网关。发现报文不包含名字、邀请码、金额或旅行密钥。无互联网 Wi-Fi 和移动数据同时开启时，只把对应 TCP socket 绑定到匹配的 Wi-Fi 本地路由，不改变应用或云连接的默认网络。

蓝牙使用 Android 原生安全 RFCOMM，服务 UUID 为 `5ccf780d-e4ee-4ebc-9b9d-5230d423c171`。两端都启用“蓝牙备用通道”；首次选择同伴手机并确认系统配对。应用只主动连接选中的已配对同伴，保存本机连接选择；第一次收到具有相同旅行密钥的有效同步后，可记住来连的同伴。之后重连不必重新扫描或配对。“忘记应用中的同伴连接”只清除应用选择，不解除系统配对、不删除账目。

Android 12 及以上分别申请 CONNECT、SCAN、ADVERTISE 所需的附近设备权限。Android 10/11 仅在查找新设备时申请前台精确位置权限，并检查位置总开关；使用已配对设备不要求位置扫描。拒绝授权、无蓝牙硬件、关闭蓝牙时，离线记账与热点通道仍可使用。应用不强行开关系统热点或蓝牙。

## 同步、补传与切换

`PeerSync` 统一管理两个传输适配器；`PeerProtocol` 只依赖有序输入输出流。已知属于同一设备的两个地址共用一次主动会话调度，热点优先。连接失败按 5、10、20、40、60 秒退避；退避期间可以选择蓝牙，不会因重复发现而清除退避。网络变化关闭失效 TCP 连接，清除过期地址并重新发现。空闲约每 30 秒校准；本地记账或收到新记录后主动安排同步。“重新连接并补传”允许用户立即清除退避重试。

新版协议流程：

1. 建立 TCP 或 RFCOMM 字节流，创建随机会话 ID；使用原有每趟旅行的 AES-256-GCM 密钥验证双方持有相同旅行。
2. 交换加密的记录数量和内容摘要。摘要相同时不发送完整历史；不同则交换 ID／SHA-256 索引，只发送对方缺少的记录。
3. 约 48 KB 明文一批加密传输。每批完整接收、认证和校验后，通过 SQLite 事务提交，再计入保存确认。半帧不会入库；已提交的批次在下一次会话中不会重复发送。
4. 双方完成各自方向后，用绑定旅行、会话、设备 ID 与本次数据帧摘要的 HMAC 保存确认。未收到有效确认时继续显示待连接／待重试。
5. 确认丢失、后台中断、进程重启后，从持久化流水重新比较索引，不依赖只存在内存中的待发队列。传输中新增的本地记录由下一轮校准补传。

记录沿用全局 UUID、原录入时间戳、各币种最小金额单位和删除标记。重复事件不重复计账；相同 ID 但内容不同会回滚当前批次并保留原账目，不按设备时间覆盖。每次会话只导入本机仍存在且密钥一致的旅行。不同设备分别录入同一笔真实付款会生成不同 ID，仍需避免双方重复手工记账。

TCP 建连超时约 3.5 秒，蓝牙建连约 10 秒；15 秒无读写进展或会话总时长超过 180 秒关闭连接，包含阻塞写入。单帧限制 12 MB，每趟旅行最多同步 10,000 条记录，每次会话接收总量限制 32 MB。错误密钥、认证失败、截断、格式错误和冲突均不宣告同步成功；正常已提交批次继续保留。

Windows v0.1.5 与安卓可在同一热点使用 v2，电脑通过 mDNS 和 UDP 发现同伴。电脑先保存收到的记录，再发出确认。未知版本的地址直连先用 v1 协商，两端识别对方支持 v2 后改用增量同步。Windows v0.1.4 可通过 v1 交换记录。不同 Wi-Fi 时可继续使用邀请码配置的 HTTPS 服务。

## 已验证与实机验收

Android 10（API 29，官方 AOSP x86_64）和 Android 16.1（现有 API 36 镜像）分别通过 45 项独立测试包检查，覆盖生产 SQLite、加密、TCP、UDP、协调器及界面。两个逻辑设备通过真实回环流交换数据；蓝牙调度测试注入同样的有序流，验证自动切换与数据一致性，不代表真实蓝牙无线链路已经验收。既有网页／桌面／服务端 44 项回归通过。[结果留档](../tests/results/android-peer-2026-11-05.json)不含真实账本；最终 APK 在 Android 10 上安装、启动成功，沿用上一版调试签名。

实体双机验收步骤：

1. 安装同一调试版 APK，一端创建含虚构金额的旅行，另一端加入；先断开热点并关闭蓝牙，两端分别记账、关闭重开，核对本机记录保留。
2. 关闭移动数据，一端开启热点，另一端连接，打开两端应用，核对全部流水、原始资金、换汇、删除和各币种结果一致。再次同步应无新增。
3. 预先确认蓝牙配对并在两端启用备用通道。继续记录后关闭热点，确认无需选通道即可经蓝牙补传；记录较多时中断蓝牙，再开启并核对补传无重复。
4. 重新开启热点，检查优先恢复热点；同时开启移动数据、热点没有互联网时也能直连。更换热点地址后再次检查。
5. 拒绝附近设备／位置授权、关闭位置或蓝牙、单端切到后台、杀进程后重开，检查可继续本地记账且重连后补传。蓝牙仍拒绝授权时只测试热点。

真实双机的热点 mDNS／UDP 支持、配对弹窗、无线干扰和厂商后台策略尚待验收。目前同步在两端应用前台运行；不承诺锁屏、后台或任意厂商机型即时同步。此双人协议只处理两人账本；0.2 小队使用本页前述的另一套协议。

参考 Android 官方文档：[蓝牙权限](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)、[双端 RFCOMM 连接](https://developer.android.com/develop/connectivity/bluetooth/connect-bluetooth-devices)、[NSD 服务发现](https://developer.android.com/develop/connectivity/wifi/use-nsd)。
