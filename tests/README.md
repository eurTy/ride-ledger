# 邀请码与同步验证

## 2026-11-05 安卓双通道

新增生产热点 TCP、备用 UDP 发现和蓝牙 RFCOMM 适配器，共用加密增量协议与 SQLite 去重。Android 10（API 29，官方 AOSP x86_64 镜像）和 Android 16.1（API 36，现有镜像）分别通过 45 项原生检查，覆盖下列新增场景；网页／桌面／服务端既有 44 项回归仍通过。结果留档在 [android-peer-2026-11-05.json](results/android-peer-2026-11-05.json)。最终发布 APK 也已在 Android 10 上安装和启动，包版本 0.1.5、minSdk 26、targetSdk 35，调试签名证书与 v0.1.4 一致。

- 两个独立 Android SQLite 副本、任意分片的有序流、加密摘要／索引对账、相同摘要不重传、下一轮只发送一笔新记录。
- 约 48 KB 分批传输中断、进程内重开数据库后补缺失批次；最终确认丢失、跨通道重试不重复计账。
- 密文损坏、错误邀请码密钥、伪造保存确认、同 ID 不同内容事务回滚；删除标记、乱序时间戳、交换中新增记录不丢失。
- v1 未知端点协商与旧版 TCP／AES-GCM 互通，保留设备身份、原有数据库与账目。
- 路由策略的热点优先、失败退避、重复发现不清退避、热点地址变化；真实 `PeerSync` 协调器接入注入的流，验证热点失败后自动走蓝牙、热点恢复后重新优先。
- 阻塞读和阻塞写都会被 watchdog 关闭，工作线程可释放；UDP 请求与回复发现双方且不会无限回声。
- Android 10/11 与 12+ 权限分支；实际启动生产界面，检查无蓝牙授权时离线快速记账、打开蓝牙设置、关闭备用通道、再次打开仍保留一笔账目。

测试包仍为独立的 `com.rideledger.synctest`，不读取用户账本。界面检查会创建虚构旅行，并短暂启动本机 NSD／UDP 发现（发现信息仅含随机设备 ID 和端口，没有邀请码或流水）。蓝牙协调器检查使用注入流，**未替代两台实体安卓的配对和无线测试**。实机步骤及限制见 [安卓直连说明](../docs/android-peer-sync.md)。

Android 10 首次开机的镜像需先连接其虚拟 AndroidWifi，否则所有宿主机 HTTP/TCP 检查会因无网络失败，回环协议检查仍可通过。无需改变手机代码绕过网络。

2026-11-04 使用虚构旅行与独立中转服务执行。网页／桌面协议／服务端测试 44 项通过，安卓模拟器检查 26 项通过，另完成两端邀请码、AES-GCM 数据互通。新增公网流程调用真实 Electron 客户端、临时 HTTPS 入口和真实安卓代码，3 项安卓公网连接检查通过。测试使用独立用户目录，安卓测试包使用应用 ID `com.rideledger.synctest`，结束后卸载。

## 验证范围

| 场景 | 核对结果 |
| --- | --- |
| 甲或乙分享邀请码、自己的第二台设备加入、旧邀请码 | 旅行 ID、密钥、中文与 Emoji 名字保持一致；默认身份正确，手动选择自己的身份可用 |
| 重复加入、无效代码、字段错误、密钥错误 | 不覆盖已选身份，不导入错误旅行或记录；本地保存失败不留下仅在内存中的旅行 |
| 双方离线加入与录入，关闭后重开，再连接同一服务 | 最终获得完整流水；金额、币种、时间戳、付款人、删除标记保持一致 |
| 一端网络不可达、HTTP 503、连接拒绝、响应截断 | 本地记录保留，显示待重试，连接恢复后可继续同步 |
| 服务已存下上传，但响应丢失 | 重试后不重复入账；另一端能取得已上传记录 |
| 响应延迟时继续记账、密集触发同步 | 新录入不会被旧响应覆盖；同一客户端不会同时发起重复同步 |
| 重复、倒序快照和已删除流水 | 不重复计算支出，旧快照不会使已删除流水重新生效 |
| 损坏快照混在正常快照之前 | 跳过损坏数据，继续导入其他正常记录，并保留待重试提示及实际新增数量 |
| 同名但不同 ID 的旅行、错误密钥 | 不串账；原有旅行和记录不受影响 |
| 等待响应期间删除本地旅行 | 返回的旧响应不会重新创建旅行 |
| 中转服务关闭并重新启动 | 已上传快照保留；未上传的本地记录可在重试后交换 |
| 两端使用不同中转服务地址 | 数据暂时独立；通过新邀请码更新到同一地址后收敛。旧邀请码未携带服务地址 |
| 安卓 TCP 长度头、数据体分段到达或中途断开 | 完整帧正常合并；半帧不写入，重试后恢复；重复帧不重复计账 |
| 邀请码包含 HTTPS 连接，已有旅行更新连接 | 只配置当前旅行，身份和流水保留，不覆盖其他旅行的地址 |
| 安卓旧版数据库升级与重开 | 原有原始资金和流水保留；新连接地址可持久保存 |
| 电脑版与安卓通过真实公网入口互通 | 安卓仅粘贴邀请码，即可下载电脑账目、上传离线记录；重开后仍自动使用该旅行的地址 |
| 独立 EXE 关闭与重新运行 | 账目及当前旅行保留；运行环境随 EXE 打包，无需本机安装 Electron 或 Node.js |

## 运行

先运行 `npm install` 安装项目依赖，再使用现有 Node.js 运行网页、桌面协议与本地中转服务测试：

```powershell
npm test
```

安卓检查使用已有 Android SDK、JDK 和已启动的模拟器。默认路径与项目打包脚本一致，默认模拟器序列号为 `emulator-5554`。首次检出需先运行 `./build-debug.ps1` 生成本地调试密钥，再运行：

```powershell
node tests/run-android-sync.mjs
```

可通过 `ANDROID_SDK_ROOT`、`JAVA_HOME`、`ANDROID_TEST_SERIAL` 指定现有工具和模拟器。测试结果及系统版本写入 `build/android-sync-tests/report.json`；完整 instrumentation 输出在同目录。独立测试包调用生产代码中的 SQLite、邀请码解析、AES-GCM、HTTP、TCP、UDP 与界面实现；界面检查启动发现服务，但不会向 Wi-Fi 广播旅行密钥或金额。

真实客户端与公网流程在已安装项目开发依赖后运行：

```powershell
node tests/run-desktop-flow.mjs --public --android
npm run desktop:package
node tests/run-desktop-flow.mjs --packaged --public --android
```

该流程实际操作客户端表单，覆盖原始资金、共同与个人支出、补充现金、还款、换汇和金额核对；关闭重开后再通过公网与独立模拟设备交换记录。安卓端不会手填同步地址。报告写入 `build/desktop-flow-report/report.json`；临时公网入口随客户端关闭而结束。

## 本轮修复

- 网页同步增加 15 秒请求超时，连接一直无响应时允许后续重试。
- 网页与安卓按快照分别处理错误，避免一份损坏数据阻断其他正常记录；安卓局域网失败提示保留已导入数量。
- 统一旅行 ID 格式和邀请码字段校验；旧邀请码仍可加入，换行粘贴可用。
- 网页先成功保存加入的旅行，再更新当前页面状态。

## 实测边界

安卓环境为现有 Android 16.1 模拟器。两条独立故障注入链路模拟不同网络连接同一服务；TCP 测试覆盖实际安卓读写和合并代码。尚未覆盖两部实体手机的热点自动发现、热点设备隔离，以及不同厂商系统的后台限制。同步仍需双方有共同可达的热点或中转服务，应用打开时运行。

公网验证经过真实外网 HTTPS 地址，但安卓设备仍是模拟器。用户的一台真实手机接入另一 Wi-Fi 后的操作需在该手机上完成。
